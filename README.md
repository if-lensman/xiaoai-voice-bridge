# 小爱语音桥

**LX04 豆包语音终端＋NAS Docker 中转。**

项目名：**小爱语音桥** · 仓库名：`xiaoai-voice-bridge`

说“豆包豆包”，听它回答，也在屏幕上看到自己说的话和豆包的回复。音箱负责交互，NAS Docker 负责中转，日常使用无需电脑常开。

> 非官方个人开源项目，已在自有 LX04 上运行。适合愿意使用 Android、ADB 和 Docker 的动手玩家。

![LX04 真实界面的两轮对话布局测试](docs/public/assets/screen-dialogue.png)

*上图是真实音箱界面的两轮布局测试，文字为测试内容。*

这是普通 Android APP，应用名为“豆包对话”，使用 Android 前台服务保持本地唤醒；不会替换小爱的系统桌面。

## 可以做什么

| 功能 | 当前情况 |
|---|---|
| 本地唤醒 | 说“豆包豆包”进入对话，待机识别在音箱执行 |
| 连续语音 | 一次唤醒后连续问答，回答完恢复聆听 |
| 两轮字幕 | 上方保留上一轮简记，下方突出当前问答；识别和回答随当前轮更新 |
| 触屏控制 | 开始对话、打断播报、结束对话、回到小爱界面 |
| 自动待机 | 说“再见”等结束词，或安静约 45 秒，关闭当前云端会话 |
| 常驻与自启 | 音箱前台服务开机启动，NAS 容器常驻中转 |
| 唤醒词打断 | 已接入播报中再喊“豆包豆包”的控制路径，距离和口音仍需更多实测 |

**已实测：LX04，系统 2.42.118 Release。** 其他型号和固件尚未验证。触屏打断已验证，普通说话直接抢话所需的完整全双工回声消除尚未实现。

## 它怎么工作

```mermaid
flowchart LR
    A[小爱音箱\n唤醒 · 录音 · 播放 · 字幕] <-->|局域网设备令牌| B[NAS Docker\n音频转换 · 会话中转]
    B <-->|加密 WebSocket| C[豆包实时语音]
```

语音 Key 留在 NAS，音箱只保存中转地址和设备令牌。只有唤醒进入会话后，本项目才向中转发送麦克风音频。这不代表原装小爱自身的联网行为发生了改变。

## 动手前，先确认四件事

1. **权限已经准备好。** 当前安装需要事先具备已授权的 root ADB 环境。APP 本身不提供提权功能，本仓库不介绍如何获取设备权限。
2. **供电稳定。** 实测设备曾因供电不足在播报时重启，改善供电与音量后恢复。遇到重启，先排除供电问题。
3. **语音服务已开通。** 使用豆包语音控制台的实时语音服务 Key，火山方舟的通用推理 Key 不适用于这里。
4. **NAS 可运行 Docker 并访问语音服务。** 当前 NAS 为 ARM64；中转不需要显卡、USB 或 ADB。

## 日常使用

- 开始：说“豆包豆包”，或点“开始对话”。
- 继续：等回答结束后，接着说。
- 打断：点“打断”；播报中也可试喊“豆包豆包”。
- 结束：点“结束对话”，说“再见 / 结束对话 / 不聊了”，或等待空闲超时。
- 回原界面：点“回到小爱”，结束当前云端对话并返回原桌面，本地唤醒继续运行；再说“豆包豆包”即可回来。

## 源码怎么分

```text
android/             本地唤醒、音频收发、会话控制
screen/              Android APP、两轮界面、开机服务
relay.py             实时语音协议与打断流程
host_service.py      常驻中转与最小健康状态
screen_text.py       当前轮、上一轮与迟到事件处理
setup_relay.py       生成自己的中转私有配置
install_terminal.py  安装和配置音箱终端
build_*.py           Android 构建
test_*.py            音频、协议和字幕的离线测试
```

正常运行不保存录音、对话原文、逐轮日志或会话历史。中转只保留必要健康状态，异常时仅输出错误类型。源码中不包含调试录音、运行记录和旧版限时测试入口。

## 验证和范围

已验证本地唤醒、多轮问答、字幕、触屏打断及结束、空闲回待机、音箱重启自启、NAS 容器重启恢复，以及停用电脑中转后的实际播报。现有自动检查共 28 项，另用真实豆包接口验证了打断后新一轮的恢复。

这仍是一套 LX04 实践实现，尚未验证全部距离、口音、音量和其他硬件型号。豆包属于联网服务，开通条件、额度与计费以服务商控制台为准。
