# 音箱和 NAS 如何分工

音箱已有屏幕、麦克风和扬声器，负责交互；NAS 长期开机，负责保管语音 Key 和中转。电脑只在开发与安装时使用。

待机时，本项目在音箱上识别唤醒词。唤醒后，音箱通过带设备令牌的局域网连接发送音频；NAS 再通过加密 WebSocket 连接豆包。

音箱采集 16 kHz 双声道 PCM，中转选取已验证的麦克风通道，滤波、增益和封包。回答返回后转换为音箱可播放的 PCM，同时传递文字和状态。

屏幕只保留两轮：上方是上一轮的简要问题与回复片段，下方是当前完整问答。新一轮以用户语音事件为边界，不依赖某个模型版本才会返回的 `response.created`。

用户识别结果是“当前完整猜测”，每次覆盖上一版；豆包回答在当前轮内流式更新，并兼容逐步增长的完整前缀。重复事件和已结束轮次的迟到片段不应再拼回当前轮。上一轮摘要由已有文字截取，不另调模型生成结论。

普通对话采用半双工，播报时不将本项目的回采音频上传模型。触屏打断立即清空本地缓冲，通过 `response.cancel` 取消回答，确认后恢复聆听，保留会话。

语音打断采用明确唤醒词：播报中再次说“豆包豆包”，触发同一取消流程。普通说话直接抢话还需要完整回声消除和更多真机验证。

打断时冻结旧轮，标注“已打断”，新轮等待下一个问题。摘要保留的是当时已经收到的回复片段，不能视为精确到字的实际播报位置。

结束对话会关闭当前云端会话，返回本地待机。“回到小爱”会同时结束当前会话并返回原桌面，后台唤醒继续保留；再次唤醒会打开对话页。本项目不替代原装小爱的全部功能，也不对其独立联网行为作保证。
